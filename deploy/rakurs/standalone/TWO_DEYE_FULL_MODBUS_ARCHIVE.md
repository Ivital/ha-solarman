# Rakurs: два паралельні Deye SUN-20K-SG05LP3-EU-SM2 зі спільною АКБ

## Статус, 24.11.2026
- Два фізичні інвертори заявлені користувачем, але немає доступу до них.
- Порти моніторингу, Master/Slave, Modbus-адреси, прошивки і BMS не перевірені.
- База `rakurs` містила один старий *синтетичний* Deye та каталог 624
  Modbus-полів / 815 адрес регістрів. Попередній архів зберігається без змін.
- Нові записи створюються лише як **два незалежні синтетичні пристрої**.
  Кожен має `kind='simulation'`, `quality='simulated'`,
  `ingest_source='rakurs_parallel_sim_seed_v1'`. Серійні номери, адреси,
  ролі та підтвердження зв'язку не вигадуються.
- Таблиця групи відображає планову систему 2 × 20 кВт, 48 В спільна АКБ.
  Це паспортна потужність і топологічне припущення на основі повідомлення
  власника, а НЕ 40 кВт фактичної генерації.

## Архітектура збереження
- `rakurs_parallel_groups`: модель, 2 слоти, спільна батарея, статус unverified.
- `rakurs_parallel_members`: приналежність кожного пристрою та ідентичність
  simulated/physical, роль і Modbus-адреса (NULL, доки не підтверджені).
- `rakurs_modbus_poll_runs`: окремий протокол *кожного* циклу опитування,
  його UID, час, transport, slave ID, кількість запитів/відповідей/помилок.
- `rakurs_modbus_frames`: байти *кожного* запиту і відповіді, винятки,
  таймаути; `request_bytes` та `response_bytes` не заповнюються вигаданими
  пакетами під час симуляції.
- `rakurs_modbus_register_samples`: кожне отримане слово 0..65535 для
  функцій Modbus FC03/FC04 окремо з device_id, poll_id, frame_id і адресою;
  **без фільтра по 815 адресах каталогу**. Повторне зчитування адреси в іншому
  кадрі не затирається.
- `rakurs_modbus_bit_samples`: кожен біт FC01/FC02, якщо опитування
  повертає дискретні значення.
- `rakurs_modbus_field_samples`: існуючий архів 624 полів з можливістю
  зберегти `raw_registers_json`, numeric/text, device_id, quality.
- `rakurs_samples`: існуючі 316 показників UI та часові ряди.
- `rakurs_device_events`: лише справжні події/аварії з конкретного приладу.

**Повнота** означає ВСІ успішно отримані байти/слова/біти та помилки
фактичних спроб опитування. Не можна називати 815 наявних адрес «усі регістри
інвертора» до звірки з його firmware та офіційним профілем. Невідомі
адреси, якщо вони прочитані, теж архівуються.

## Безпечний одноразовий запуск на ergodata-lnx
```bash
cd /home/ivital/deye-monitoring-src
git pull --ff-only
bash deploy/rakurs/standalone/deploy_full_modbus_archive.sh --check
sudo -v
bash deploy/rakurs/standalone/deploy_full_modbus_archive.sh --apply
```
`--check` не змінює MySQL. `--apply` вимагає інтерактивного підтвердження,
прихований пароль локального адміністратора БД та **успішний повний
`mysqldump`** у каталозі `/var/backups` з правами 0700. Якщо
`mysqldump` відсутній або резервне копіювання неуспішне, операція
припиняється БЕЗ змін БД. Шість нових таблиць лише створюються, жодна
існуюча таблиця не очищується/не змінюється. Два тестові набори й
приналежність до групи записуються в одній транзакції.

Очікуваний приріст до поточної БД після успіху:
- +2 пристрої `simulation` (НЕ фізичні інвертори);
- +2 Modbus poll runs;
- +1630 синтетичних сирих регістрових слів (815 ×2);
- +1248 синтетичних розшифрованих полів (624 ×2);
- +632 синтетичних показники UI (316 ×2);
- +2 набори Modbus frames; кількість кадрів залежить від розривів адрес.
- Стара історія (~135936 записів додавання) залишається без змін.
- Кількість фізичних зареєстрованих інверторів залишається **0**.
  Окремий підрозділ сайту показує синтетичні дані з явним попередженням.

Перевірка:
```bash
sudo -u rakurs env RAKURS_DB_USER=rakurs_web \
  RAKURS_DB_PASSWORD_FILE=/etc/rakurs/mysql_password \
  /var/lib/rakurs/.venv/bin/python \
  /home/ivital/deye-monitoring-src/deploy/rakurs/standalone/audit_two_inverters_mysql.py
```

## Контракт для майбутнього реального колектора (поки НЕ запускати)
Лише після підтвердженої фізичної схеми, двох ідентичностей, адрес,
режиму зчитування та регістрів:

```json
{
  "device_key": "verified_real_deye_1",
  "poll_uid": "unique_20261124_213000_device1",
  "observed_at_utc": "2026-11-24T21:30:00Z",
  "quality": "good",
  "ingest_source": "verified_read_only_collector",
  "transport": "rs485",
  "slave_id": 1,
  "frames": [
    {
      "sequence_no": 1,
      "function_code": 3,
      "start_address": 1000,
      "requested_count": 2,
      "status": "ok",
      "request_hex": "010303e80002",
      "response_hex": "01030400010002",
      "words": [1, 2]
    }
  ],
  "fields": [],
  "signals": []
}
```

Це **контракт демонстраційного формату**, не підтверджений дамп Deye;
hex-пакети наведено як схематичні байтові приклади, не як коректні RTU/CRC
кадри або дозволені адреси. Перед реальним опитуванням потрібні
протокольна перевірка CRC/MBAP, функцій, діапазонів та адрес.

Локальна перевірка файлу:
```bash
python3 deploy/rakurs/standalone/archive_modbus_capture.py /path/to/poll.json
```
Вона не виконує мережевих запитів, не відкриває RS485 і не змінює базу.
Режим `--apply` для реального колектора вимкнений до окремого введення в
експлуатацію, перевірки джерела й налаштування спеціального DB-акаунта.
**Ніяких функцій запису Modbus 05/06/15/16 немає**.

## Правила коректної агрегації
- PV: лише незалежні локальні потужності, синхронні свіжі вимірювання,
  окремі `device_id`; не сумувати системні значення Master двічі.
- Load/Grid: спільний лічильник/CT або підтверджені вимірювання.
- SOC: лише одна BMS спільної АКБ; **не додавати** відсотки двох Deye.
- Температура й аварії: окремо по кожному; загальний ризик визначати
  за активним/невідомим станом кожного.
- Якщо хоча б один інвертор недоступний, відмітити баланс неповним.
