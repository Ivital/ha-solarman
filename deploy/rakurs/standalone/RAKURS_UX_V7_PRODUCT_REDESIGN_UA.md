# RAKURS UX V7 — повна переробка продуктового інтерфейсу

Статус: архітектура і критерії приймання; **не реліз**. Дата аналізу: 2026-11-26.
Репозиторій: `Ivital/ha-solarman`, гілка `feature/deye-trb145-monitoring`.
Порядок змін: GitHub → GitHub Actions → ізольований preview з реальними архівними даними read-only → візуальний QA на Android/desktop → штатний guarded deploy. Ніяких змін безпосередньо на сервері.

## 1. Мета

На мобільному екрані користувач повинен за 3–5 секунд бачити:
1. Онлайн/архів/немає даних, час останнього **фактичного вимірювання**;
2. Генерацію PV від Deye №1 і Deye №2 (окремі масиви);
3. Навантаження, мережу, акумулятор і SOC як **фізично спільні вузли**;
4. Напрямки потоків лише там, де документально перевірені регістри і знаки;
5. Наявні попередження — без пошуку в технічних вкладках.

Перший екран — **енергетичний стан**, а не полотно з величезними картками та анімаціями. Наступний екран — інтерактивний графік; технічні деталі — після натискання.

## 3. Діагностика чинного Rakurs

Станом на аналіз: `app-parallel-twin-20261125.js` ≈2015 рядків, окремий `rakurs-energy-board-20261126.js` ≈345 рядків,
`rakurs-energy-board-20261126.css` ≈827 рядків із накопиченими mobile overrides,
`rakurs-color-20261125.css` ≈439 рядків; один шаблон підключає багато CSS-файлів.
Тимчасові CSS-переозначення й псевдоелементи створювали розірвані лінії та різну геометрію на різних телефонах.

Проблеми: головна сторінка надто висока; дані й графіки нижче видимого екрана;
схематичне «рухання» архівних величин схоже на живі покази;
покази спільної АКБ, мережі й навантаження з двох інверторів різняться;
тексти/плашки/індикатори дублюють одне одного; умовні точки/стрілки не формують ясної структури.

## 4. Обов'язкові фізичні та інформаційні обмеження

- Два паралельні SUN-20K-SG05LP3-EU-SM2; PV №1 і PV №2 окремі.
- ОДНА фізична АКБ, ОДНА мережа, ОДНЕ навантаження.
- Покази Deye №1/№2 для спільних вузлів — незалежні **повідомлення/джерела**, не два фізичні вузли.
- Не додавати SOC, load_power, grid_power, battery_power без перевірки семантики Modbus і походження регістрів.
- Навіть PV1+PV2 сумувати лише після звірки типу показника, одиниці та часової узгодженості.
- Історичні потужності (кВт) і добові енергії (кВт·год) — різні величини.
- Поточний `DEYE_V1053_REGISTER_AUDIT_UA.md` — аудит адрес (755 документальних, 815 профільних, 290 перетин), **не доказ семантичної сумісності SG05LP3**.
- Відсутність вимірювання ≠ нульовий обмін. Відсутні/сумнівні покази позначати як «—» і пояснювати в деталях.
- Архівні дані позначати конкретною датою; ні за яких умов не показувати архів як «зараз».
- До фізичної верифікації Modbus — нуль команд і нуль небезпечних записів. UI read-only.

## 5. Продуктова інформаційна архітектура

### Мобільний Огляд (ширина 360–430 px)

```text
RAKURS                                  ◷ Архів
Останній запис: 25.11, 00:16

┌───────────────────────────────────────────┐
│          ДВА МАСИВИ PV                   │
│      ☀ PV 1             ☀ PV 2           │
│       5,1 кВт           5,432 кВт        │
│          ╲               ╱              │
│           ╲   [Deye ×2] ╱               │
│              ● вузол                     │
│    ┌──────────┼───────────┐              │
│    ▼          ▼           ▼              │
│  Будинок      АКБ        Мережа          │
│  6,4 кВт      SOC 72%     0 кВт          │
│             1,3 кВт                       │
└───────────────────────────────────────────┘
[24 год] [7 днів] [30 днів]   [Переглянути]
[графік: PV1, PV2, будинок, АКБ, мережа]
[2 Deye: діагностика]          [Події]
[Огляд] [Інвертори] [Графіки] [Історія] [Розділи]
```

Це СТРУКТУРНА схема, значення лише приклади історичних значень зі скриншотів, а не актуальні вимірювання.
Екран не повинен копіювати схему вище буквально; мінімальні контрасти й радіуси визначає дизайн-система.

Правила:
- Перший екран без великого заголовка-слогана, багатослівних описів і повторних KPI-карток.
- Стислий статус доступності + час вимірювання помітний одразу.
- Компактні, однорідні округлені вузли на одному SVG полотні або одному вимірюваному контейнері; **жодних CSS pseudo-elements для фізичних зв'язків**.
- Цільова висота схеми на мобільному ≈320–430 CSS px залежно від ширини, без відривів/горизонтального скролу.
- Під схемою відразу видимі мініграфік і вибір діапазону часу.
- Натискання на будь-який вузол відкриває нижню sheet-панель з деталями й джерелом регістра; дотик поза нею або «Закрити» закриває її.
- Існуюча мобільна нижня навігація залишається; окрему вкладку «Графіки» можна зробити основною замість «Сонце» тільки через окремий UX-тест.

### Десктоп

Дві колонки: зліва помітна flow-схема та стислий стан, справа графік/показники і список подій. Нижче — діагностика 2 Deye, деталізовані графіки, журнал.
Інформація та логіка спільні з мобільною, змінюється тільки адаптивне компонування.

### Поглиблені сторінки

`/parallel`: два інвертори, окремі PV, статуси, параметри, порівняння за ОДНАКОВИМ часом.
`/trends`: наочний графік, підписи осей, курсор часу, легенда/вмикання серій.
`/history`: фільтр дати/часу, експорт CSV тільки за явним запитом, без прихованого запису.
`/events`: простий список з важливістю, часом, пристроєм, статусом.
`/registers`: таблиця, технічні метадані, статус «документальна адреса» vs «апаратно підтверджено».

## 6. Модель достовірності перед UI

Новий стабільний `view-model` для кожного показника:
`{ key, value, unit, device_key, slot, register_address, firmware_profile, measured_at_utc, quality, confidence, scope, sign_convention }`.

Для спільного вузла `scope=system` лише за перевіреним системним лічильником/регістровим джерелом. Інакше `scope=device_report` і підпис «Архів Deye №...», а у деталях — обидва повідомлення та розбіжність.
`quality=live|stale|missing|unverified|conflicting`, причому `live` залежить від апаратної верифікації, poller, часу і доступності.

Стан схеми не повинен показувати напрямок, якщо знаковість не перевірена, є конфлікт або бракує даних.

**Анімація:** у live — рух за перевіреним напрямком; в архіві — нерухомий кадр. За явною дією «Відтворити архів» — анімація історичної шкали часу з видимим режимом playback та timestamp. Повага `prefers-reduced-motion`.

## 7. Візуальна система (єдина)

- Мова: українська. Без технічних трактатів на головній.
- Нейтральний теплий світлий фон або високоякісна темна тема; без градієнтів у кожній картці.
- Основний колір взаємодії — синій; генерація — бурштиновий; АКБ — зелений/бірюзовий; мережа — фіолетовий; споживання — теплий червоний; помилки — семантично червоні.
- Колір завжди дублюється зрозумілою іконкою/напрямом/підписом (доступність).
- Точки дотику мін. 44×44 CSS px, контраст тексту рівня WCAG AA, системні шрифти без сторонніх файлів, цифри `tabular-nums`.
- Єдиний scale spacing (4/8/12/16/24 px), border radius 12–16 px, тіні дуже делікатні.
- SVG зв'язки: узгоджені вузли та реальні краї карток, криві без розривів, один стиль наконечників; без текстових unicode-стрілок або набору незалежних псевдоелементів.
- Нуль: тонкий нейтральний зв'язок; відсутні дані: «—» та індикатор несправності/відсутності, не «0».
- Серія анімації спокійна й функціональна; відсутність надмірного світіння, мерехтіння або декоративних рухів.

## 8. Технічна реалізація

1. Не розширювати поточний `rakurs-energy-board-20261126.css` черговою порцією override.
2. Створити незалежний V7 компонент із семантичним HTML, одним SVG для схеми, єдиною системою design tokens та окремим adapter/view-model.

4. Feature flag з можливістю повернутися на чинний V6, поки не прийнято дизайн. Не змінювати production.
5. Перевірити lazy loading історії та дедуплікацію запитів; не збільшувати frontend bundle без потреби.
6. Візуальний/скріншотний тест справжнім браузерним рендерингом, а не лише пошук рядків у CSS. Без visual QA — NO DEPLOY.

## 10. Рішення щодо релізу

Поточний Rakurs залишити робочим і незміненим. Наступний етап — **повноцінний V7 redesign на окремому preview**, поєднаний з data-quality contract і E2E screenshot QA. Після приймання — звичайний GitHub → guarded deploy. Не змішувати UX redesign із фізичним підключенням RS485.


## Актуалізація продуктового дизайну

Штатний URL без параметрів. Енергетична мнемосхема використовує самостійні SVG-зображення PV, двох інверторів, АКБ, будинку та мережі, без прямокутних KPI-вузлів. Єдина палітра оболонки, вкладки, компактний графік, дата та показники вибраного часу, повернення до останнього запису. Всі збережені показники MySQL доступні у звичайному режимі; службове походження залишається в даних і не змінює їх відображення. Факт фізичного підключення та поточність вимірів не підміняються станом бази.


## Єдина система внутрішніх сторінок

Всі 15 чинних маршрутів збережено. Каталоги сигналів — ключові показники та компактний повний перелік із пошуком; графіки — точна вісь часу, вибір запису мишею/дотиком/клавіатурою, розриви довгих прогалин. Сторінка інверторів — окремі пристрої та згортання технічних регістрів. Архів — без додаткової колонки походження у звичайній таблиці, CSV зберігає службове поле quality. Налаштування, події, довідник, Modbus і система мають спільну типографіку, таблиці й адаптивні відступи. Додано браузерний прохід усіх внутрішніх маршрутів на мобільному і desktop, перевірку інтерактивності графіків та відсутності горизонтального переповнення.


## Єдиний робочий інтерфейс і анімація

Експериментальний параметр `ux` перенаправляється на штатний URL. Попередню енергетичну дошку та дубльовані блоки прибрано з HTML. Старі файли дошки більше не входять до маніфесту релізу; штатний інсталер переносить їх у резервну копію та видаляє з каталогу сервісу з автоматичним відкатом у разі помилки. Історичний код лишається в Git для відтворення старих регресій. Анімація відображає ненульові значення обраного запису: PV і позитивне навантаження мають напрямок, АКБ/мережа без підтвердженого знака — пульсацію без напрямку; нулі та відсутні дані нерухомі. Рух можна призупинити, системна перевага reduced-motion враховується. Не змінюються база, колектор, налаштування і захист.


### Напрямок АКБ та мережі
Знак збереженої потужності інтерпретується за конвенцією Deye (АКБ + розряд, − заряд; мережа + імпорт, − експорт). Відображається звіт обраного інвертора, не сума. Протилежні знаки або несумісні одиниці блокують однозначну стрілку; нуль не анімується. Підтвердження фактичної полярності регістрів при введенні в експлуатацію залишається необхідним.


### Аудит компактності та архівного зрізу
Скорочено висоту мобільної мнемосхеми з 307 до 269 одиниць SVG, прибрано дубль кнопки деталізації та статусу, діагностику перенесено до підвалу схеми, зменшено панель навігації. Усі шість серій графіка увімкнені за замовчуванням. Архівний зріз включає окремі звіти обох Deye для виявлення розбіжностей, але на графіку і схемі спільні вузли не дублюються. За відсутності записів у вибраній даті історичні значення не підміняються останніми. Відкриття інспектора призупиняє відтворення архіву.


### Внутрішні сторінки історії та архіву
Графіки та історія запитують спільний період від останнього запису вибраного Deye (`anchor=latest`), зворотна сумісність API за `anchor=now` збережена. Архів за замовчуванням відкриває 72 години від останнього запису. Поля дати використовують Europe/Kyiv незалежно від часового поясу браузера. CSV фіксує параметр і інвертор саме виконаного запиту, а не нового вибору; текстові поля екрануються. Таблиця явно позначає обмеження 50 видимих рядків.


### Розширена аналітика та швидкодія
Порівняння двох Deye в розділі графіків з однаковим часовим та вертикальним масштабом. Енергетичні звіти доба/місяць/рік — різниця накопичувальних лічильників між наявними точками, з межами покриття; зменшення лічильника блокує розрахунок. Не підсумовуються спільні показники. Окремі фазні блоки, діагностика BMS та модулів із Δ напруги при синхронних даних. Масштаб/панорамування графіків кнопками та двопальцевим жестом. Огляд перевіряє MySQL кожні 30 с у видимій вкладці, оновлює лише змінений компонент і не перериває вибраний архів/інспектор. Групові запити latest оптимізовано до одного SELECT; продукційні індекси не змінюються.


### Початкове завантаження без спалаху старих карток
Початковий HTML показує компактний стан завантаження, а серверний резервний блок має `hidden` ще до виконання JS. Після успішного читання API монтується V7; лише підтверджена помилка запускає `restoreServerReadings()` і відкриває резервні значення. Без JS доступне посилання `/deye`. Chromium перевіряє відсутність видимих карток без JS, при навмисно затриманому API та повторному завантаженні на мобільному/десктопі, а також видимість резерву при відмові API.


### Оперативна модернізація 27.11.2026
Графіки використовують адаптивну серверну вибірку реальних перших/останніх/мінімальних/максимальних точок по часових сегментах. CSV читає окремі сирі сторінки з точним UTC-курсором, до 100000 записів за експорт. Історичні кадри не підставляють сусідні значення. Таймаут API 15 секунд; ручне оновлення перечитує статус і каталог. Порівняння Deye на одному SVG з єдиним курсором і масштабом, MPPT, фазні діаграми, профілі обладнання, зведення двох інверторів, фільтри та пагінація подій, оперативна діагностика системи. Для мобільного Modbus — компактне відображення рядків. Повний фізичний баланс, підтвердження декодування, покоміркові дані й прогнози не підміняються розрахунками без підтверджених джерел.
