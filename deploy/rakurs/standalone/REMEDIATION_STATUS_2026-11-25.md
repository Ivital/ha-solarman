**Дата:** 25.11.2026, Europe/Kyiv  
**База:** звіт `RAKURS_CODE_AUDIT_2026-11-25.md`, 29 пунктів  
**Гілка:** `feature/deye-trb145-monitoring`  
**Режим:** GitHub-код і CI; **жодних прямих змін працюючого MySQL, Nginx, systemd або фізичних інверторів**.

> Увага: PASS у CI підтверджує тести вихідного коду. Це не підтверджує
> розгортання на `ergodata-lnx`, фактичний TLS на `192.168.5.30`,
> успішне ізольоване відновлення MySQL або реальні відповіді Deye.

## Реалізовано в коді

| H-05 | Перше реальне вимірювання не переводить повністю системний огляд у live-режим; потрібні два підтверджені свіжі члени | Фактичних live-джерел нині немає |

| H-07 | Приймання живого кадру звіряє `slave_id` з перевіреною адресою члена групи | Потрібна ще прив'язка до реального gateway identity, serial/firmware |

| H-12 | Дві тестові картки не залежать від неповного старого SSR API | Потрібне підтвердження в браузері |

## Принципові обмеження, які не можна позначати PASS

1. **C-01. Реальний collector**. Немає підтвердженої фізичної лінії від кожного SUN-20K-SG05LP3-EU-SM2 до Teltonika/Modbus. Заборонено навмання посилати запити, змінювати Master/Slave або використовувати паралельний/BMS порт як телеметрійний. Немає безперервного активного collector service.
2. **C-02/M-15. Firmware-specific карта та затвердження**. Наявні 815 адрес/624 поля походять із P3 профілю інших SG04LP3/SG01HP3. Для SG05LP3 жоден реальний register map не підтверджений. Мапу й фактичні значення потрібно звірити зі специфікацією і контрольною сесією, після цього затвердити конкретний `serial+firmware+register profile`.
3. **H-01/H-02/H-04 — інфраструктурні міграції**. На робочому MySQL ще **не** встановлено перевірений TLS trust anchor і не підтверджено змінені grants та таблицю fingerprint. Старий вебдоступ поки використовує LAN plaintext. До цього реальні записи заблоковані.
4. **M-05/M-08/M-12**. Не виконувалися ізольоване відновлення backup, production-подібні MySQL integration tests, браузерний E2E та навантажувальні/retention тести.
5. **M-13**. Старий `rakurs_modbus_register_inventory` досі має PK тільки за адресою. Таблиця повного RAW архіву зберігає функцію разом з адресою, тому фактично одержані слова не втрачаються; для розширеного каталогу потрібна окрема контрольована міграція inventory.
6. **Спільна АКБ**. Немає підтвердженого BMS SOC/CT і немає права сумувати двічі виміряне навантаження, потужність мережі або SOC.

## Безпечна послідовність введення у роботу

1. Перевірити GitHub CI, зберегти незмінні SHA поточного release та сервера; запустити `deploy_parallel_ui.sh --check`.
2. Виконати MySQL резервне копіювання і **реальне відновлення в окрему ізольовану БД**, перевірити таблиці, FK, рядки й SHA.
3. Видати CA MySQL і сертифікат сервера із SAN для адреси/імені, до якого фактично підключається `rakurs`, оновити облікові записи й конфігурацію без вимкнення TLS. Лише після успішного handshake встановити `RAKURS_MYSQL_CA_FILE` у службу і верифікувати.
4. Лише після restore rehearsal та TLS: окремо застосувати `apply_modbus_fingerprints.py --apply` та `harden_mysql_grants.py --apply`; перевірити на сервері фактичні GRANTS і schema. **Не запускати у цій розмові**.
5. Виконати release deployment вебкоду з backup і rollback; перевірити `/api/v1/status`, `/api/v1/parallel/simulation`, `/api/v1/parallel/health`, static assets, auth, nginx, видимість двох карток.
6. Перед реальним опитуванням здійснити **пасивний фізичний огляд**, підтвердити два serial/firmware, порт моніторингу, Modbus TCP vs Serial Over IP, топологію Master/Slave, BMS і точний register map. Після цього створити окремий колектор із двома контрольованими read-only транспортами та обов'язковим збереженням кожного прочитаного ADU.
7. Після повної верифікації — включити тільки схвалений versioned decoder, BMS source, перевірку CT, відмовостійкість, retention і відновлення.

## Контроль доступу і захисту даних

- Паролі не вводити в командний рядок, не зберігати у Git і не показувати в логах.
- Жодних веб- або Модbus-команд запису; не перепризначати RS485 без фізичної верифікації.
- **Синтетичні значення — тільки simulation**, у БД вони залишаються без змін.
- Не виконувати старі `deploy_* --apply`, використовується тільки `deploy_parallel_ui.sh` для актуального вебрелізу.
- До перевіреної TLS-міграції **не запускати живий ingest** і не заявляти, що промисловий Rakurs готовий.
