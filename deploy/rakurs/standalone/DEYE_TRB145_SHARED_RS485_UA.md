# Rakurs — два Deye SUN-20K-SG05LP3-EU-SM2 через один Teltonika TRB145

**Редакція:** 25.11.2026 · **статус:** код підготовлено, фізична топологія та реальна телеметрія **ще не підтверджені**.

## Підстава та межі достовірності

- [Deye SUN-(14–20)K-SG05LP3-EU-SM2, посібник виробника](https://www.deyeinverter.com/deyeinverter/2024/10/08/%E5%82%A8%E8%83%BD%E4%B8%89%E7%9B%B8-sun-14-20k-sg05lp3-eu-sm2.pdf): у паралельному прикладі наведено `Modbus SN` 01/02/03; у додатку є `Modbus RJ45` для віддаленого моніторингу. Розділ 3.3.2 при цьому позначає порт як *Reserved*. Потрібна перевірка маркування й конфігурації конкретної апаратної ревізії.
- [Developer089/deye-modbus-ha](https://github.com/Developer089/deye-modbus-ha/blob/main/README.md): підтримує `Modbus unit ID`, Modbus TCP (логер або RS485–TCP gateway), RTU-over-TCP; FC03 для читання, FC16 для запису. Це **референс архітектури**, але не перевірена карта регістрів Deye 20 кВт. Профілі в `models.py` заявлені до 12 кВт.
- [Teltonika TRB145 Modbus documentation](https://wiki.teltonika-networks.com/view/TRB145_Modbus): режим `Modbus TCP over Serial Gateway`; за правильного режиму `Server ID` може братися з TCP-повідомлення. Залежить від встановленої версії RutOS/прошивки.

## Логічна схема (не схема монтажних клем)

```text
Сервер Rakurs → VPN → TCP/IP → Teltonika TRB145 (один master)
                                      │
                         RS485 2-wire half-duplex A/B
                                      │
                          ┌───────────┴───────────┐
                          │                       │
                   Deye №1 Modbus RJ45     Deye №2 Modbus RJ45
                   Unit ID 01*             Unit ID 02*
                   
Окремо: Deye Parallel_A/B ↔ CAN (синхронізація інверторів)
Окремо: BMS CAN/RS485 та Meter-485 — НЕ використовуються для Rakurs
```

`*` 01/02 — приклад, **не встановлені фактичні адреси**. Адреси кожного інвертора і відповідність `Modbus SN` фізичному RS485 slave встановлюються лише перевіркою.

## Контроль перед підключенням

1. Перевірити фізичну модель TRB145, справжній порт кожного Deye, шильдики та версії firmware. Не відкривати відсіки під напругою та не чіпати CAN/BMS/силові з'єднання. Монтаж виконує електротехнічний персонал після відповідного знеструмлення.
2. Звірити контакти роз'єму RJ45 з **актуальним** посібником, а не за кольором мережевого кабелю. У додатку Deye зазначаються SUNSPE-485_A/B/GND; не вважати контакти живлення TRB145 сигнальною землею.
3. Використати коректну двопровідну шинну топологію RS485 (без зіркових відгалужень), перевірити спільний потенціал/гальванічну ізоляцію, полярність та термінування лише на двох фізичних кінцях, якщо воно потрібне за фактичними схемами й довжиною лінії.
4. Перевірити встановлені `Modbus SN` та режими Master/Slave *без їх зміни*. CAN-паралель має функціонувати незалежно.
5. Для режиму **Modbus TCP gateway** забезпечити передачу Unit ID з MBAP до RTU (в TRB145 — `Server ID: Obtained from TCP`, якщо такий режим доступний). Якщо шлюз налаштований як **transparent serial TCP**, надсилати повний RTU-кадр з CRC, не звичайний MBAP. Не змішувати ці режими на одному TCP-порту.
6. Після підтвердження фізичного з'єднання виконати по одному контрольованому **read-only** FC03 на узгоджений з документацією регістр для адрес обох інверторів; перевірити окремі відповіді та UID, CRC/MBAP, час, серійні/firmware і реалістичність показників.
7. Лише після підтвердження карти регістрів саме 20 кВт дозволяти застосунку декодувати й публікувати живі дані. Майстер/система/CT, спільний SOC, імпорт/експорт та живлення АКБ **не сумуються двічі**.

## Що реалізовано в GitHub

- Конфігурація вебсайту зберігає **IP, TCP порт, транспорт, Modbus Unit ID, FC03/FC04, обмежений діапазон** для кожного Deye.
- Для двох фізичних інверторів з одним gateway IP:port сервер блокує повторний Unit ID та несумісні режими `modbus_tcp` / `rtu_tcp`.
- `shared_rs485_buses` в `GET /api/v1/config` показує лише стан записів налаштувань, не видає його за факт фізичної наявності лінії.
- Незалежна перевірка в колекторі **відхиляє весь конфліктний gateway endpoint** перед будь-яким запитом; запити виконуються послідовно, не конкурентно.
- Сторінки «Керування» та «Паралельна система» показують схему, параметри інверторів, стан підтвердження й інструкцію.
- Дозволені тільки FC03/FC04. Віддалений запис FC05/FC06/FC15/FC16 відсутній. Історичні записи MySQL залишаються без змін.

## Що ще не зроблено

Немає підтвердження реальних RS485 кабелів, параметрів Teltonika й відповіді кожного Deye, перевіреної firmware-specific карти регістрів 20 кВт та схваленого введення в експлуатацію. Не вмикати `rakurs-poller` без цієї перевірки. CI, API чи наявні історичні дані не доводять фізичну роботу обладнання.

**Деплой:** `deploy_parallel_ui.sh --check` → резервна копія → `--apply` тільки через контрольовану процедуру GitHub-to-server з перевіркою PHP/Flask API, Nginx, авторизації, HTTPS статичних ресурсів та rollback. Скрипт UI не змінює фізичні пристрої і не вмикає колектор.
