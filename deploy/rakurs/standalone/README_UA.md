# Rakurs Standalone — власний MySQL без Home Assistant

> **Актуальне доповнення, 25.11.2026:** поточний RAKURS уже
> розгорнуто на https://rakurs.zakryttya.org.ua/; після видалення
> застарілого одиночного Deye в MySQL залишено два історичні профілі.
> Текст нижче описує початкову процедуру міграції 24.11.2026.
> Новий адміністраторський екран **«Керування»**, інтервал опитування,
> параметри інвертора, ізольована інсталяція таблиць та
> **вимкнений за замовчуванням** фізичний poller описані в
> [POLLING_OPERATIONS_UA.md](POLLING_OPERATIONS_UA.md).
> Код конфігураційної площини не підтверджує фізичну достовірність
> наявних архівних записів; опитування не вмикати без аудиту портів.


Нова цільова архітектура Rakurs — незалежний вебдодаток з єдиною
базою MySQL 8.0.45 на 192.168.5.30, база rakurs. Жодних запитів
до Home Assistant, його Recorder, SQLite, датчиків або API немає.

**Стан на 24.11.2026:** код окремого вебінтерфейсу та локальної
авторизації готовий у GitHub, але ще НЕ встановлений на Debian як
робочий сайт. Існуючий HTTPS-сайт поки обслуговує HA.

## Реалізовано в коді

- Власний український вебінтерфейс із 10 розділами: Огляд, Сонце,
  Акумулятор/BMS, Мережа, Навантаження, Інвертор, Історія, Події,
  Архів, Система.
- Каталог 316 планових сигналів із позначкою, що вони ще не
  перевірені на конкретному Deye SG05LP3.
- Стан підключення, пристрої, перевірені сигнали, останні вимірювання,
  часові ряди, події та журнали отримання з п'яти таблиць MySQL.
- Вимірювання лише з MySQL і тільки для сигналів verified=1; порожня
  БД показує тире і повідомлення про відсутність реальних даних.
- Ліміт історії — 1000 останніх точок за 1–168 годин; неактивні
  показники не замінюються фіктивними значеннями.
- API тільки SELECT із параметризацією, без записів у MySQL.

## Обмеження та безпека

Реалізовано локальну авторизацію: логін, хеші паролів scrypt,
браузерні сесії з підписом, 8-годинний термін, CSRF, вихід із
системи, 15-хвилинне блокування після повторних невдалих входів.
Користувачі й лічильники спроб зберігаються тільки в MySQL rakurs
(дві додаткові auth-таблиці). Немає стандартних паролів.
**MFA поки не реалізовано.** Публічний доступ слід дозволяти
лише після перевірки HTTPS, входу, виходу і прав користувачів.

До перевірки слухати лише
127.0.0.1:8765, без змін Nginx, DNS і брандмауера.

Вебсервіс працює під системним користувачем rakurs із MySQL акаунтом
rakurs_web@192.168.5.31, якому потрібен SELECT на rakurs.*, INSERT/UPDATE
на rakurs_login_attempts і UPDATE на rakurs_users для останнього входу.
Не використовувати широкі права Ivital@% у вебсервісі.

Пароль лише в локальному файлі з правами 0600, який належить
користувачу процесу. Змінна RAKURS_DB_PASSWORD_FILE вказує шлях.
У GitHub, командному рядку, історії shell і чаті пароль не зберігати.
Згідно з рішенням власника, TCP MySQL у внутрішній мережі без TLS;
порт 3306 не відкривати в Інтернет.

## Змінено порядок демонтажу за рішенням власника (24.11.2026)

Home Assistant не містить необхідної робочої телеметрії, тому
власник дозволив **негайно прибрати старе середовище**, до запуску
нового Rakurs. Для цього додається окремий режим `--remove-now`:

~~~bash
cd ~/deye-monitoring-src
git pull --ff-only
bash deploy/rakurs/standalone/migrate_rakurs.sh --remove-now
~~~

Перед видаленням скрипт перевіряє назву й Compose-мітки контейнера,
коректний bind-mount, відсутність інших контейнерів на цих файлах
та конфігурацію тільки домену Rakurs. Потім переводить **лише**
`rakurs.zakryttya.org.ua` у тимчасовий режим технічного оновлення
(HTTPS 503, НЕ 502), зупиняє HA, зберігає перевірену резервну копію
й лише після цього видаляє старий контейнер, його config і
невикористаний Docker image. Nginx, Docker, Odoo, Ergodata, MySQL
та ІТМ залишаються. До запуску нового застосунку сайт показуватиме
технічне оновлення, а не панель HA.

**Не виконувати `--remove-now` двічі.** Режим `--retire`
після нього не потрібен. Потім виконати `--prepare`, `--publish`;
скрипт публікації вміє замінити і старий HA vhost, і відому
maintenance-конфігурацію. `--prepare` вимагає нових паролів,
але не відновлює HA.

## Єдиний сценарій із трьома контрольованими етапами

Замість ручного повторення численних команд запустити read-only аудит:

~~~bash
cd ~/deye-monitoring-src
git pull --ff-only
bash deploy/rakurs/standalone/migrate_rakurs.sh --status
~~~

Після аудиту та, якщо обрано, негайного демонтажу можна виконувати інтерактивні етапи окремо:

1. --prepare: додає auth-таблиці, ставить сервіс, створює окремі
   облікові записи MySQL і вебадміністратора, перевіряє локальну роботу.
2. --publish: перевіряє авторизацію й перемикає лише Rakurs HTTPS
   із резервною копією старого Nginx vhost і автоматичним відкатом.
3. --retire: тільки якщо старий HA раніше НЕ видаляли, після приймання сайту прибирає старий контейнер,
   його локальні файли й непотрібний HA Docker image без примусу.
   Резервна копія HA зберігається для відкату.

Режими --remove-now, --prepare, --publish та --retire запускаються по одному через
інтерактивний термінал. Не запускати --retire до успішної перевірки
входу до нового Rakurs через HTTPS. Не змінювати Odoo/Ergodata/ІТМ.

## Порядок безпечного переходу на новий Rakurs

Початкові дії збережено в окремих перевірених скриптах:

1. Оновити вихідні файли та виконати перевірку:

~~~bash
cd ~/deye-monitoring-src
git pull --ff-only
bash deploy/rakurs/standalone/apply_auth_schema.sh --check
bash deploy/rakurs/standalone/stage_standalone.sh --check
bash deploy/rakurs/standalone/retire_homeassistant.sh --audit
~~~

2. Додати дві таблиці авторизації до існуючих п'яти без видалення
будь-яких даних:

~~~bash
bash deploy/rakurs/standalone/apply_auth_schema.sh --apply
~~~

3. Встановити незалежний сервіс у /opt/rakurs без перемикання
працюючого сайту й без зупинки HA:

~~~bash
bash deploy/rakurs/standalone/stage_standalone.sh --install
~~~

4. Створити окремий MySQL account rakurs_web@192.168.5.31,
локально згенерувати/захистити файл пароля та створити
першого вебадміністратора:

~~~bash
sudo /var/lib/rakurs/.venv/bin/python \
  deploy/rakurs/standalone/provision_mysql_web_user.py
sudo /var/lib/rakurs/.venv/bin/python \
  deploy/rakurs/standalone/bootstrap_admin.py
~~~

Для bootstrap_admin.py потрібен веблогін і новий пароль
мінімум 16 символів, які вводяться приховано. Ні GitHub, ні чат
їх не отримують. Скрипти не перевстановлюють і не мігрують MySQL.

5. Лише після цих дій запустити ізольований сервіс:

~~~bash
sudo systemctl enable --now rakurs-standalone.service
bash deploy/rakurs/standalone/switch_rakurs_nginx.sh --check
~~~

6. Після приймання входу та API без Home Assistant:

~~~bash
bash deploy/rakurs/standalone/switch_rakurs_nginx.sh --apply
~~~

Цей перемикач змінює тільки Rakurs HTTPS vhost, робить backup
і відкат у випадку помилки. Сертифікат HTTPS зберігається.

7. Лише після успішного перемикання й окремої перевірки:

~~~bash
bash deploy/rakurs/standalone/retire_homeassistant.sh --audit
bash deploy/rakurs/standalone/retire_homeassistant.sh --remove-ha
~~~

Останній сценарій видаляє лише контейнер deye-homeassistant і його
локальний config bind mount після контрольної резервної копії.
Двигун Docker, Nginx, Odoo, Ergodata та Teltonika не чіпає.

**Режим --remove-ha старого скрипта вимагає завершеного перемикання;
для негайного демонтажу використовуйте тільки --remove-now.** Якщо MySQL акаунт Ivital не має права CREATE USER,
процедура зупиниться, а не змінюватиме загальні привілеї.

## API (тільки GET)

- /api/v1/status — підключення, кількість пристроїв і сигналів.
- /api/v1/catalog — список планових показників, НЕ покази приладу.
- /api/v1/signals — перевірені сигнали.
- /api/v1/latest?keys=pv_power,battery_soc — фактичні останні значення.
- /api/v1/history?key=pv_power&hours=24 — фактична історія.
- /api/v1/events — події.
- /api/v1/devices — зареєстровані пристрої.
- /api/v1/batches — журнал циклів отримання.

## Залишкова робота

Незалежну авторизацію на паролі вже реалізовано, MFA ще не готова.
Автоматичне опитування Deye не активувати, поки Teltonika обслуговує ІТМ.
Зовнішнє резервування MySQL та перевірка відновлення залишаються
окремими задачами експлуатації.

Існуючий HA-контейнер і його SQLite **не використовуються новим Rakurs**.
До підтвердженого виконання --remove-now стан сервера не вважати зміненим.
