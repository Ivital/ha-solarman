# Фізична топологія Rakurs: два паралельні Deye

Дата уточнення: 26.11.2026. Підстава: опис конфігурації власником системи.

## Підтверджене користувачем компонування

- Окремі сонячні панелі (PV) Deye №1 та PV Deye №2.
- Спільні для двох паралельно включених інверторів: навантаження, зовнішня мережа та акумуляторна батарея.
- На мнемосхемі рівно два входи PV та по одному фізичному вузлу для навантаження, мережі й АКБ.
- Один спільний вузол має один графічний зв'язок зі спільною енергетичною шиною, не по два.

## Межі даних Modbus

Два інвертори можуть повертати різні значення щодо спільних вузлів (наприклад, їхні власні внески або некалібровані звіти). Значення `load_power`, `grid_power`, `battery_power`, `battery_soc` без індивідуальної звірки регістрів **не вважати підтвердженим балансом усієї системи**.

На головній показувати останній запис одного чітко зазначеного джерела (обраного Deye), без арифметичного додавання. Розбіжність телеметрії позначати; детальні звіти обох Deye показувати в поясненні спільного вузла. Якщо два звіти дають протилежні знаки напрямку, не показувати визначений напрямок у режимі «Уся система».

Не плутати підтверджену користувачем *схему електричних з'єднань* із непідтвердженим фізичним Modbus-зв'язком. Останній не увімкнено; усе в інтерфейсі лишається архівним і read-only.


## Узгодження спільних архівних значень (27.11.2026)
На вимогу власника будинок (`load_power`) та рівень заряду (`battery_soc`) для однакових UTC DATETIME(6) узгоджуються за Deye №1. Операція `sync_shared_archive.sql` стосується тільки існуючих записів офлайн-архіву від `rakurs_preview_history`, за вимкненого опитування, без зміни часу, кількості рядків, сирих регістрів і походження. Невідомі/відсутні пари не доповнюються. Фактичні фізичні вимірювання не перезаписуються. Windows-скрипт спочатку робить повну захищену резервну копію. Розбіжності звітів винесено з головної панелі до інженерного режиму; реальні помилки доступності не приховуються.
