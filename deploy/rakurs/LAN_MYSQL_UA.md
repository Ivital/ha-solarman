# Rakurs — локальна MySQL (актуально з 24.11.2026)

**ВИМОГА ВЛАСНИКА:** тільки наша база MySQL rakurs, без Home Assistant
для показників, історії, звітів та подій. Готується окремий вебдодаток
у папці standalone; опис і план переходу — standalone/README_UA.md.
Поточний HA-сайт не перемикали. П'ять таблиць MySQL уже створені.

Сервер: `192.168.5.30`; база: `rakurs`; TCP за замовчуванням: `3306`.
Клієнт Rakurs/Home Assistant: `192.168.5.31`.

Попередній зовнішній хост `kshz1.mysql.tools` і база `kshz1_rakurs`
**скасовані для Rakurs**. Не використовувати старі інструкції TLS зовнішнього
хостингу. У GitHub немає паролів нової MySQL. Ім'я користувача MySQL — `Ivital`. Підтверджено право створення
таблиць і SELECT; інші права не перевірялися.

## Перевірка зв'язку (зараз)

```bash
cd ~/deye-monitoring-src
git pull --ff-only
bash deploy/rakurs/mysql_archive_preflight.sh --network
```

Ця команда робить лише TCP-connect до 192.168.5.30:3306, без пароля,
SQL і змін в MySQL. Якщо FAIL — перевірити MySQL bind-address, дозвіл
для клієнта 192.168.5.31 і firewall тільки на сервері 192.168.5.30.
Не відкривати 3306 в Інтернет або для всього LAN без потреби.

## Авторизація (після підтвердження доступності TCP)

Потрібен користувач MySQL з доступом до БД `rakurs` з
`192.168.5.31`. Ім'я можна передати як змінну, пароль вводиться
приховано, не зберігається в скрипті:

```bash
RAKURS_DB_USER='Ivital' \
  bash deploy/rakurs/mysql_archive_preflight.sh --login
```

`--login` використовує незашифрований MySQL TCP у контрольованій локальній мережі
**за рішенням користувача**, без TLS і сертифікатів. Облікові дані й
вимірювання передаються мережею без захисту TLS; тому мережа повинна бути
довіреною, а порт 3306 — доступним тільки з сервера Rakurs `192.168.5.31`.
Скрипт не вимикає TLS на самому MySQL-сервері, а лише використовує
`--ssl-mode=DISABLED` або `--skip-ssl` на клієнті. Якщо сервер вимагає
захищений транспорт, підключення завершиться помилкою; серверні політики
самостійно не послаблювати.

Скрипт виконує тільки `SELECT` і `SHOW SESSION STATUS`. Він не
створює таблиць, не змінює Home Assistant або ІТМ.

## Результат застосування схеми — ПІДТВЕРДЖЕНО

24.11.2026 користувач виконав `mysql_archive_apply_schema.sh --apply`
на `ergodata-lnx`. Збережено фактичний результат:

```text
LOCAL_SCHEMA_VALIDATION=PASS; EXPECTED_NEW_TABLES=5
RAKURS_EMPTY_DATABASE_CONFIRMED
RAKURS_TABLES=5
RAKURS_SCHEMA_VERIFY_PASS
rakurs_device_events
rakurs_devices
rakurs_ingest_batches
rakurs_samples
rakurs_signals
RAKURS SCHEMA INSTALL COMPLETE (5 EMPTY TABLES, NO SAMPLE DATA)
```

Створення п'яти таблиць **завершено**, `--apply` **не повторювати**.
За виводом інсталятора всі таблиці створені порожніми, але
поточний фактичний лічильник рядків після інсталяції окремо не перевірявся.

**Автоматичний архів вимірювань ще не запущений.** Таблиці не є джерелом
телеметрії. Потрібні фізичне підключення Deye, перевірка правильності
його регістрів/сутностей і окремий ingestion-адаптер з обмеженими правами.
Поки TRB145 обслуговує ІТМ, не виконувати опитування Deye через її
поточний TCP/RS485 канал. Не вигадувати тестові виміри.

## Призначення БД

Rakurs Standalone буде читати й зберігати всі вимірювання лише в
MySQL `rakurs` на 192.168.5.30. Home Assistant Recorder не входить
до нової архітектури. Поки працює попередній сайт, його SQLite не змінюємо. Схему з 5 таблиць у файлі
`archive_mysql_schema.sql` **вже застосовано**. Реального
запису телеметрії немає, доки Teltonika обслуговує ІТМ та не
підтверджені регістри Deye. Чужі БД і сервіси не змінювати.

## Створення порожніх таблиць після успішної авторизації

24.11.2026 підтверджено MySQL `8.0.45`, користувача `Ivital@%`,
`DATABASE=rakurs`, `Ssl_cipher` порожній, `TABLES=0`.
Це означає, що база порожня та LAN-з'єднання без TLS працює.
Право `CREATE` не перевірено.

Підготовлений інсталер має два режими:

```bash
cd ~/deye-monitoring-src
git pull --ff-only
bash deploy/rakurs/mysql_archive_apply_schema.sh --check
bash deploy/rakurs/mysql_archive_apply_schema.sh --apply
```

`--check` лише локально перевіряє точний перелік DDL і не підключається
до MySQL. `--apply` вимагає ручного підтвердження назви `rakurs`,
а пароль зчитує приховано клієнт MySQL. Перед будь-яким CREATE у тій
самій сесії перевіряє, що активна БД = `rakurs` і жодних таблиць немає.
Створює виключно 5 порожніх таблиць із
`archive_mysql_schema.sql`, після чого перевіряє загальну кількість
таблиць і виводить `SHOW TABLES`.

Важливо: п'ять CREATE TABLE не утворюють однієї транзакції MySQL;
якщо виникає помилка після першої таблиці, попередні залишаться.
Не перезапускати `--apply` після помилки без інспекції.
Не зачіпає SQLite Home Assistant, інші MySQL-бази, Teltonika або ІТМ.
